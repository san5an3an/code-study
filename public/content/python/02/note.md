# 02. 파이썬 개발환경 구성(windows)

## 이 강의에서 배우는 것

- 인터페이스와 사용자 인터페이스(UI)가 무엇인지
- UI의 두 종류: 명령어로 다루는 **CLI**, 그림(아이콘)으로 다루는 **GUI**
- 윈도우에서 CLI 환경인 **명령 프롬프트**를 여는 법 (윈도우키 + R → `cmd`)
- **IDE**(통합 개발 환경), **소스 코드**, **텍스트 파일**, **확장자**의 뜻과 윈도우에서 확장자를 보이게 하는 법
- 윈도우에 개발 환경 만들기: 파이썬 설치 → JupyterLab 설치 → Visual Studio Code 설치

> 복습: 01강에서 프로그래밍 언어와 번역(컴파일, 인터프리터) 이야기를 했어요. 이번 강의는 코드를 거의 쓰지 않고, 앞으로 코드를 쓸 **작업대**를 컴퓨터에 차리는 시간이에요. 강의는 윈도우 11 기준이고, 맥 설치는 다음 강의에서 따로 다뤄요.

## 1. 인터페이스와 사용자 인터페이스(UI)

**인터페이스(Interface)** 는 **사람과 컴퓨터를 연결해 주는 장치**예요. 강사님이 "연결"에 동그라미를 치면서 이 단어가 중요하다고 짚었어요.

슬라이드에 나온 예시는 모두 인터페이스예요.

- 모니터, 키보드, 마우스
- 태블릿 PC나 스마트폰의 터치스크린
- 그림 그릴 때 쓰는 펜 태블릿

**사용자 인터페이스(UI, User Interface)** 는 인터페이스의 대상을 **소프트웨어로 좁힌** 개념이에요. 슬라이드 정의는 "사용자와 컴퓨터가 상호 작용하는 프로그램의 일부분"이에요. 쉽게 말해 사람과 프로그램 사이를 이어 주는 화면이나 방식이에요.

강사님 말로는 프로그래밍을 하면서 "인터페이스"라는 말을 정말 많이 듣게 되니까 뜻을 꼭 기억해 두라고 해요.

## 2. CLI와 GUI

UI는 크게 두 가지예요.

| 구분 | 이름 | 다루는 방식 | 대표 예 |
|---|---|---|---|
| **CLI** | Command Line Interface, 명령어 라인 인터페이스 | 사용자가 명령어를 **글자로 입력**하고, 결과를 **글자 메시지**로 받아요 | 윈도우의 명령 프롬프트 |
| **GUI** | Graphic User Interface, 그래픽 사용자 인터페이스 | 화면의 구성 요소가 **그림(그래픽)** 으로 나오고, 마우스나 터치로 눌러요 | 윈도우의 바탕화면, 웹사이트, 스마트폰 앱 |

- 요즘 우리가 주로 쓰는 건 GUI예요. 아이콘이 있고 그걸 마우스로 클릭하는 환경이에요. 그래서 GUI에는 아이콘을 누를 **마우스나 터치스크린**이 필요해요.
- CLI는 "좀 옛날 환경"이에요. 옛날에는 이런 환경을 **DOS(도스)** 라고 불렀고, 윈도우에는 그 DOS가 **명령 프롬프트**라는 프로그램으로 들어 있어요.
- 일반 사용자는 CLI를 잘 안 쓰지만, 강사님 말로는 프로그래밍을 공부하면 **굉장히 많이 다루게** 돼요. 앞으로 파이썬에 기능을 추가로 설치할 때도 여기에 명령어를 쳐요.

## 3. 윈도우에서 명령 프롬프트(CLI) 열기

1. 키보드 왼쪽 아래의 **윈도우 로고 키**와 **R**을 같이 눌러요. (R은 Run, 즉 "실행"이에요.)
2. 화면 아래에 **실행** 창이 떠요.
3. 열기 칸에 `cmd`를 입력하고 **엔터**를 누르거나 **확인** 버튼을 눌러요.
4. 검은 창이 뜨고 `C:\Users\사용자이름>` 뒤에서 커서가 깜빡이면 명령어를 입력할 수 있는 상태예요.

> **강의와 다른 점**: 강사님은 명령 프롬프트의 영어 이름이 "커맨더(commander)"라서 줄여서 CMD라고 했는데, 영어 이름은 **Command Prompt**이고 `cmd`는 **command**(명령)를 줄인 거예요. 실행 파일 이름도 창 제목에 보이는 대로 `cmd.exe`예요.

> **참고(강의 밖 내용)**: 창 제목과 경로에 `C:₩Windows₩system32₩cmd.exe`처럼 `₩`가 보이는데, 08강에서 배우는 것처럼 한글 글꼴에서 **역슬래시(`\`)** 가 `₩`로 보이는 거예요. 같은 글자예요. 또 요즘 윈도우 11에는 명령 프롬프트 대신 **터미널(Windows Terminal)** 이 먼저 뜨기도 하는데, 그 안에서 똑같이 명령어를 쓸 수 있어요.

## 4. IDE(통합 개발 환경)

프로그래밍을 하면 크게 네 가지 일을 해요.

| 활동 | 뜻 |
|---|---|
| **코딩** | 특정 프로그래밍 언어로 구체적인 컴퓨터 프로그램을 구현하는 기술 |
| **디버그(디버깅)** | 프로그램의 정확성이나 논리적인 오류(버그)를 찾아내는 테스트 과정 |
| **컴파일** | 소스 코드를 실행 가능한 형태로 바꾸는 처리 |
| **배포** | 최종 사용자에게 소프트웨어를 제공하는 과정 |

**IDE(Integrated Development Environment, 통합 개발 환경)** 는 이 모든 작업을 **하나의 프로그램 안에서** 할 수 있게 해 주는 소프트웨어예요.

- 강사님은 디버깅에 별표를 치면서 "어떻게 보면 코딩보다 더 중요한 과정"이라고 강조했어요.
- IDE 종류는 아주 많은데, 이 강좌에서는 마이크로소프트가 만든 **Visual Studio Code(VS Code)** 를 써요. 전 세계에서 가장 유명하고, 무엇보다 **무료**예요.

> **참고(강의 밖 내용)**: VS Code는 엄밀히 말하면 "코드 편집기"이고, 파이썬 같은 언어 기능은 **확장(Extension)** 을 깔아서 붙여요. 확장까지 깔면 IDE처럼 쓸 수 있어서 강의처럼 IDE라고 불러도 괜찮아요.

## 5. 소스 코드, 텍스트 파일, 확장자

### 소스 코드

코딩을 해서 만드는 결과물이 **소스 코드**예요. 슬라이드 정의는 "**고급 언어로 작성된 프로그램 명령문이 저장되어 있는 텍스트 파일**"이에요. 고급 언어는 01강에서 배운 3세대, 4세대 언어(파이썬 같은 언어)예요.

- **텍스트 파일**: 사람이 읽을 수 있는 문자(텍스트)들이 저장된 문서 파일이에요. 메모장으로 열리는 `.txt` 파일이 대표적이에요.
- 소스 코드도 결국 텍스트 파일이에요. 메모장으로 만든 텍스트 파일의 **확장자를 바꾸면** 소스 코드가 돼요.
- 강사님 정리: 결국 **프로그래밍을 한다는 것은 소스 코드를 작성하는 것**이에요.

| 확장자 | 무슨 파일 |
|---|---|
| `.py` | 파이썬 소스 코드 |
| `.ipynb` | 주피터 노트북 파일(파이썬을 확장한 주피터 환경에서 쓰는 파일). 이 강좌에서 주로 써요 |

### 예제 (code/source_code_example.py)

슬라이드에 소스 코드 예시로 나온 `01-numeric.py` 화면을 옮긴 거예요. 이런 글자들이 담긴 텍스트 파일이 소스 코드예요.

```python
a = 123
b = -456
print(a)
print(b)

a = 10000
print(a)
```

실행 결과:

```
123
-456
10000
```

### 확장자

**확장자**는 파일의 형식이나 종류를 알려 주려고 파일 이름 뒤에 **마침표와 함께** 붙이는 영단어예요. 예를 들어 `이름.avi`는 동영상, `이름.mp3`는 음악이에요.

> **강의와 다른 점**: 슬라이드에는 확장자가 "일반적으로 알파벳 3글자로 구성된다"고 적혀 있는데, 이 강좌에서 쓰는 `.py`는 2글자, `.ipynb`는 5글자예요. 세 글자는 흔할 뿐이고 정해진 규칙은 아니에요. 아래 예제를 python3 3.14로 돌려서 글자 수를 확인했어요.

### 예제 (code/file_extension.py)

```python
import os.path

files = ["hello.txt", "hello.py", "study.ipynb", "movie.avi", "song.mp3"]

for name in files:
    stem, ext = os.path.splitext(name)   # (이름, 확장자) 두 개로 나눠 줘요
    print(name, "->", "이름:", stem, "/ 확장자:", ext, "/ 글자 수:", len(ext) - 1)
```

실행 결과:

```
hello.txt -> 이름: hello / 확장자: .txt / 글자 수: 3
hello.py -> 이름: hello / 확장자: .py / 글자 수: 2
study.ipynb -> 이름: study / 확장자: .ipynb / 글자 수: 5
movie.avi -> 이름: movie / 확장자: .avi / 글자 수: 3
song.mp3 -> 이름: song / 확장자: .mp3 / 글자 수: 3
```

> **참고(강의 밖 내용)**: `for`, `os.path.splitext` 같은 문법은 뒤 강의에서 배워요. 지금은 "파일 이름을 이름 부분과 확장자 부분으로 나눌 수 있다" 정도만 보고 넘어가면 돼요. `len(ext) - 1`은 마침표 한 글자를 뺀 글자 수예요.

### 윈도우에서 확장자 보이게 하기

윈도우는 기본으로 확장자를 **숨겨요**. 그러면 `.txt`를 `.py`로 바꾸기가 어려워서, 먼저 보이게 바꿔 둬야 해요.

- **윈도우 11**: 아무 폴더나 열고 → 위쪽 **보기** → **표시** → **파일 확장명**을 체크해요.
- **윈도우 10 이하**: 아무 폴더나 열고 → 위쪽 **보기** 탭 → 오른쪽 "표시/숨기기" 묶음의 **파일 확장명**을 체크해요.

체크하면 폴더에 보이는 파일 이름 뒤에 `.영단어`가 붙어 나와요. 그게 확장자예요.

## 6. 개발 환경 구성 순서

슬라이드에 나온 전체 순서예요.

1. 명령 프롬프트로 **파이썬 설치 여부 확인**
2. **파이썬 다운로드** 받기
3. **파이썬 설치**
4. 명령 프롬프트로 **JupyterLab 설치**
5. **Visual Studio Code 설치**

왜 둘 다 깔까요? **JupyterLab**은 웹브라우저 기반(웹페이지로 만든) 파이썬 코딩 도구예요. 파이썬 작업, 특히 빅데이터 분석이나 머신러닝에서 아주 많이 쓰지만, 브라우저에서 돌아가다 보니 쓰기가 썩 편하진 않아요. 그래서 **VS Code 안에서 주피터를 편하게 쓰는** 환경, 즉 VS Code와 주피터를 결합한 환경을 최종적으로 써요.

> **참고(강의 밖 내용)**: VS Code에서 `.ipynb` 파일을 쓰려면 VS Code의 **Python 확장**과 **Jupyter 확장**도 필요해요. 이 설치는 다음 강의(맥 설치와 VS Code 사용법)에서 함께 다뤄요.

## 7. 파이썬 설치 여부 확인하기

명령 프롬프트(윈도우키 + R → `cmd`)를 열고 이렇게 입력해요. `python` 다음 **한 칸 띄고**, **빼기 두 개**(`--`), 그리고 `version`이에요.

```
python --version
```

| 상황 | 화면에 나오는 것 |
|---|---|
| 설치되어 있음 | `Python 3.7.1`처럼 버전이 나와요 (슬라이드 예시) |
| 설치 안 됨 (메시지가 나오는 경우) | `'python'은(는) 내부 또는 외부 명령, 실행할 수 있는 프로그램, 또는 배치 파일이 아닙니다.` |
| 설치 안 됨 (실습 화면) | 그냥 `Python`이라고 한 줄만 나오고 끝나요 |

실습 화면에서는 윈도우 11(창에 `Version 10.0.22000.1455`)에서 `python --version`을 쳤더니 `Python`만 나오고 끝났어요. 강사님은 이것도 **설치 안 된 상태**이니 주의하라고 해요.

> **강의와 다른 점**: 강사님이 슬라이드 설명(10:13)에서는 "윈도우 10이면 `Python`만 나온다"고 하고, 실습(11:37)에서는 "윈도우 11이면 `Python`만 나온다"고 해서 말이 엇갈려요. 실습 화면은 윈도우 11이에요. 이건 버전 문제라기보다, 윈도우 10과 11 모두에 들어 있는 "Microsoft Store로 파이썬을 설치하라는 바로가기"가 대신 대답해서 생기는 일이에요. 윈도우 10이든 11이든 버전 숫자가 안 나오면 아직 설치가 안 된 거예요.

### 예제 (code/python_version.py)

명령 프롬프트에서 버전을 보는 것과 같은 정보를 파이썬 코드 안에서도 꺼낼 수 있어요.

```python
import sys

print("큰 버전:", sys.version_info.major)
print("3.11.1 이상인가요?", sys.version_info >= (3, 11, 1))
```

실행 결과 (이 노트를 만든 컴퓨터, 파이썬 3.14.7):

```
큰 버전: 3
3.11.1 이상인가요? True
```

> **참고(강의 밖 내용)**: 맥이나 리눅스에서는 보통 `python` 대신 `python3`로 쳐요. 이 노트를 만든 맥에서 `python3 --version`을 치면 `Python 3.14.7`이 나와요. 윈도우에서는 `py --version`도 같은 일을 해요.

## 8. 파이썬 다운로드와 설치

### 다운로드

1. 웹브라우저를 열고 **`https://www.python.org`** 에 접속해요. (강사님이 "https 따따따 점 파이썬 점 org"라고 읽었어요.)
2. 메뉴의 **Downloads**에 마우스를 올리면 "Download for Windows" 아래 버튼이 나와요. 강의 화면에서는 **Python 3.11.1**이었어요.
3. 버튼을 누르면 설치 파일이 내려받아져요.

> **강의와 다른 점**: 강의 화면의 3.11.1은 2023년 1월 기준 최신이었어요. 지금은 훨씬 새 버전이 나와 있고, 이 노트의 예제와 퀴즈는 모두 **파이썬 3.14.7**에서 확인했어요(`python3 --version`). 설치할 때는 그때 python.org에 나오는 최신 버전을 받으면 돼요. 이 강좌에서 배우는 기초 문법은 3.11과 3.14에서 똑같이 동작해요.

> **참고(강의 밖 내용)**: python.org 다운로드 화면과 설치 화면은 강의 뒤로 바뀌었을 수 있어요. 화면이 달라도 윈도우용 설치 파일을 받고, "PATH에 추가" 같은 선택지가 있으면 켜 두는 게 핵심이에요.

> **참고(강의 밖 내용)**: 강사님 컴퓨터는 맥 안에서 돌린 **ARM용 윈도우**라서 실제로 설치한 파일은 `python-3.11.1-arm64.exe`였어요. 보통의 인텔/AMD 윈도우 PC라면 `amd64`(64-bit)라고 적힌 파일을 받으면 돼요.

### 설치

1. 다운로드 폴더에서 내려받은 파일을 **더블 클릭**해서 설치 프로그램을 실행해요.
2. 첫 화면 맨 아래 **`Add python.exe to PATH`** 를 **반드시 체크**해요.
3. 가운데 **Install Now**를 눌러요.
4. 끝날 때까지 기다렸다가 "Setup was successful"이 나오면 **Close**로 닫아요.

강사님이 이번 강의에서 가장 강하게 강조한 부분이 2번이에요. 화면에 "반드시 체크"라고 써 두기까지 했어요.

- 이걸 체크하면 파이썬을 쓰는 데 필요한 컴퓨터 설정을 **자동으로** 해 줘요.
- 체크하지 않고 Install Now만 눌러서 **다시 설치하는 사람이 정말 많대요.** 체크를 안 하면 그 설정을 손으로 해야 하는데, 강사님 말로는 "그럴 바에는 지우고 다시 까는 게 더 빨라요."

> **참고(강의 밖 내용)**: PATH는 "명령어를 쳤을 때 프로그램을 찾아볼 폴더 목록"이에요. 여기에 파이썬 폴더가 들어가야 아무 위치에서나 `python`이라고 쳐서 실행할 수 있어요. 자바 강의의 환경 변수 설정과 같은 이야기예요.

### 설치 확인

1. 웹브라우저와 **열려 있던 명령 프롬프트를 모두 닫아요.** 명령 프롬프트를 **새로 열어야** 그때부터 파이썬을 알아봐요.
2. 명령 프롬프트를 다시 열고 `python --version`을 쳐요.
3. 실습 화면에서는 `Python 3.11.1`이 나왔어요. 버전 숫자가 나오면 성공이에요.

```
C:\Users\leekh>python --version
Python 3.11.1
```

## 9. JupyterLab 설치 (pip)

**주피터(Jupyter)** 는 파이썬에 설치하는 **라이브러리**예요. 강사님이 지난 시간에 말한 대로 라이브러리는 파이썬의 **확장팩** 같은 거예요.

파이썬에 라이브러리를 설치할 때는 명령 프롬프트에서 이렇게 써요.

```
pip install 이름
```

- `pip` 한 칸 띄고 `install` 한 칸 띄고, 설치할 확장팩 이름을 써요.
- 우리가 설치할 이름은 **`jupyterlab`** 이에요.

```
pip install jupyterlab
```

엔터를 치면 `Collecting jupyterlab`, `Downloading jupyterlab-3.5.2-py3-none-any.whl (8.8 MB)` 같은 글자가 쭉 나오면서 설치가 진행돼요. 네트워크 상황에 따라 금방 끝나기도 하고 오래 걸리기도 해요. (강사님도 오래 걸려서 그 사이를 편집했대요.) `pip`는 나중에 라이브러리를 배울 때 다시 자세히 다뤄요.

> **참고(강의 밖 내용)**: 강의 화면의 jupyterlab 3.5.2도 지금은 더 새 버전(4.x대)이 나와 있어서, 설치하면 그때 최신 버전이 깔려요. 또 `pip`를 못 찾는다는 메시지가 나오면 `python -m pip install jupyterlab`(윈도우에서는 `py -m pip install jupyterlab`)처럼 파이썬을 통해 pip를 부르면 돼요. 이 방법이 어떤 파이썬에 설치되는지 헷갈리지 않아서 요즘은 더 권장돼요.

## 10. Visual Studio Code 설치

1. **`code.visualstudio.com`** 에 접속해요. 주소가 기억 안 나면 검색창에 "비주얼 스튜디오 코드"라고 쳐서 나오는 **영문 공식 사이트**로 들어가요.
2. 화면 가운데 **Download for Windows (Stable Build)** 버튼을 눌러요. 강의 화면 기준으로 1.74 버전이었어요.
3. 다운로드가 끝나면 다운로드 폴더에서 내려받은 파일(강의에서는 `VSCodeUserSetup-arm64-1.74.3.exe`)을 실행해요.
4. **사용권 계약에 동의** → 다음 → 설치 위치 확인 → 다음. 특별히 바꿀 건 없고 계속 다음만 누르면 돼요.
5. 중간에 **추가 작업 선택** 화면에 체크 항목들(바탕 화면 바로가기 만들기, "Code(으)로 열기" 메뉴 추가, PATH에 추가 등)이 나오는데 **모두 체크**해요.
6. 최종 확인 화면에서 **설치**를 누르고 기다려요.
7. 끝나면 "Visual Studio Code 실행"이 체크된 채로 **종료**를 누르면 VS Code가 실행돼요.

강사님 말로는 설치가 끝난 다음부터는 **윈도우와 맥의 차이가 없어요.** 그래서 VS Code 사용법은 다음 강의에서 맥 설치 과정과 함께 설명해요.

> **참고(강의 밖 내용)**: VS Code도 강의의 1.74보다 훨씬 새 버전이 나와 있어서 첫 화면 모양은 조금 달라요. 설치 순서(동의 → 다음 → 체크 항목 모두 체크 → 설치)는 비슷해요.

## 자주 하는 실수

### 1) `Add python.exe to PATH`를 체크하지 않고 설치

`python --version`을 쳐도 버전이 안 나와요. 강사님 조언대로 **지우고 다시 설치하면서 체크**하는 게 가장 빨라요.

### 2) 설치 후 열려 있던 명령 프롬프트에서 바로 확인

설치 전에 열어 둔 창은 새 설정을 몰라서 여전히 "설치 안 됨"처럼 보여요. **창을 닫고 새로 열어서** 확인해요.

### 3) `Python`만 나왔는데 설치된 줄 앎

버전 숫자 없이 `Python`만 나오면 **아직 설치 안 된 상태**예요.

### 4) 명령어 띄어쓰기와 빼기 개수 틀림

```
python--version    (붙여 씀: 안 돼요)
python -version    (빼기 하나: 안 돼요)
python --version   (맞아요)
```

### 5) 확장자를 숨긴 채로 파일 이름을 바꿈

확장자가 숨겨진 상태에서 이름을 `hello.py`로 바꾸면 실제로는 `hello.py.txt`가 돼서 여전히 텍스트 파일이에요. 먼저 **파일 확장명 표시를 켜고** 바꿔요.
