# 12강. 클래스와 생성자 함수

## 이 강의에서 배우는 것

- 클래스(설계도)와 객체(설계도로 찍어낸 실물)가 무엇이고, 어떤 관계인지 알아봐요.
- 클래스가 **멤버 변수(필드)**, **멤버 함수(메소드)**, **생성자** 세 가지로 이루어진다는 걸 배워요.
- `new` 연산자로 객체를 만들고, **참조 변수**와 점(`.`) 연산자로 객체 안의 값과 메소드를 쓰는 방법을 익혀요.
- 접근 제어(`private`, 생략, `protected`, `public`)로 "누가 이 멤버를 쓸 수 있는지" 정하는 법을 배워요.
- 객체가 만들어질 때 맨 처음 실행되는 **생성자**를 만들고, 여러 개를 만들어(오버로드) 골라 쓰는 법을 배워요.

---

## 1. 클래스와 객체: 붕어빵 틀과 붕어빵

지금까지 우리는 `public class Test01 { ... }` 처럼 클래스를 만들고 그 안에 `main` 만 써 왔어요. 사실 자바 프로그램은 **전부 클래스 단위로** 만들어요. 이번 강의부터는 클래스를 "프로그램을 담는 그릇"이 아니라 **"새로운 자료형을 만드는 설계도"** 로 써 봐요.

비유로 시작할게요.

| 비유 | 자바 용어 | 설명 |
|---|---|---|
| 붕어빵 틀 | **클래스(class)** | "붕어빵은 이런 모양, 이런 속을 가진다"는 설계도. 틀 자체는 먹을 수 없어요 |
| 틀로 찍어낸 붕어빵 | **객체(object)** / 인스턴스 | 실제로 존재하는 물건. 하나하나가 따로따로예요 |
| 붕어빵을 찍는 동작 | **`new`** | 틀로 실물을 하나 만들어 내는 명령 |
| 팥 / 슈크림 | **멤버 변수(필드)** | 붕어빵마다 다를 수 있는 값 |

핵심은 이거예요.

1. 클래스를 **만들기만 해서는** 아무것도 생기지 않아요. 틀만 있는 상태예요.
2. `new` 로 객체를 만들어야 비로소 값을 넣고 쓸 수 있어요.
3. 같은 클래스로 객체를 여러 개 만들면, **서로 완전히 별개**예요. 한 붕어빵에 팥을 넣어도 옆 붕어빵 속은 그대로예요.

### 클래스를 이루는 세 가지

| 구성 요소 | 다른 이름 | 하는 일 | 성적 클래스의 예 |
|---|---|---|---|
| 멤버 변수 | 필드(field), 속성 | 객체가 **가진 값** | 이름, 국어, 영어, 수학, 평균 |
| 멤버 함수 | 메소드(method), 기능 | 객체가 **할 수 있는 일** | 평균 구하기, 출력하기 |
| 생성자 | 생성자 함수, constructor | 객체가 **만들어질 때 처음 할 일** | 이름이나 점수를 처음부터 넣어 두기 |

"멤버(member)"는 "클래스에 소속된 것"이라는 뜻이에요. 클래스 중괄호 `{ }` 안에 들어 있으면 그 클래스의 멤버예요.

### 클래스는 "참조 자료형"

강의 화면의 주석에 "클래스 = 참조자료형"이라고 적혀 있어요. `int`, `double` 같은 **기본 자료형**(04강)은 자바가 미리 만들어 둔 거고, 클래스는 **내가 직접 만드는 자료형**이에요. 왜 "참조"라는 말이 붙는지는 아래 3절에서 메모리 그림과 함께 설명해요.

## 2. 성적 클래스 만들어 보기

강의에서는 학생 한 명의 이름과 국어·영어·수학 점수를 담고, 평균을 구하는 `Sungjuk`(성적) 클래스를 만들어요. 강사는 `Sungjuk.java` 와 `Test01_modifier.java` 두 파일로 나눴는데, 이 노트의 `code/ClassBasic.java` 는 실행하기 쉽게 한 파일에 합쳐 두었어요.

```java
class Sungjuk {
    // 멤버 변수(필드)
    public String name;
    int kor, eng, mat;
    private int aver;

    // 멤버 함수(메소드)
    public void calc() {
        aver = (kor + eng + mat) / 3;
    }

    void disp() {
        System.out.println(name);
        System.out.println(kor);
        System.out.println(eng);
        System.out.println(mat);
        System.out.println(aver);
    }

    private void view() {}
}
```

한 줄씩 볼게요.

- `class Sungjuk {` : `Sungjuk` 이라는 이름의 설계도를 만들어요. 클래스 이름은 대문자로 시작하는 게 약속이에요.
- `public String name;` : 모든 성적 객체가 각자 가질 "이름" 칸이에요. `String` 은 문자열 자료형이에요(13강에서 자세히 배워요).
- `int kor, eng, mat;` : 국어·영어·수학 점수 칸 세 개. 같은 자료형이면 쉼표로 한 줄에 선언할 수 있어요.
- `private int aver;` : 평균 칸. 앞에 `private` 이 붙었어요. 뜻은 4절에서 봐요.
- `public void calc()` : 평균을 구하는 메소드예요. 10강에서 배운 메소드와 모양이 같은데, **`static` 이 없어요.** 객체마다 자기 점수로 계산해야 하니까요. (`static` 은 14강에서 배워요. 지금은 "클래스 안에서 객체용으로 만드는 메소드는 static 을 안 붙인다" 정도만 기억해요.)
- `aver = (kor + eng + mat) / 3;` : 메소드 안에서는 같은 클래스의 멤버 변수를 이름만으로 바로 쓸 수 있어요.

이 클래스에는 `main` 이 없어요. 설계도일 뿐이라 혼자서는 실행되지 않아요. 이클립스에서 클래스를 만들 때도 강사는 "main 체크하지 마세요"라고 해요. 실행은 `main` 이 있는 다른 클래스에서 객체를 만들어서 해요.

## 3. new 연산자와 참조 변수

### new 로 객체 만들기

```java
new Sungjuk();
```

이 한 줄이 "성적 붕어빵을 하나 찍어라"예요. `new` 를 **메모리 할당 연산자**라고도 해요. 09강 배열에서 `new int[5]` 로 칸을 확보했던 것과 같은 `new` 예요.

`Sungjuk()` 처럼 클래스 이름 뒤에 괄호가 붙어 있죠? 이건 사실 **생성자를 부르는 것**이에요. 생성자는 6절에서 자세히 봐요.

### 메모리 그림으로 보기 (힙과 스택)

컴퓨터의 메모리(RAM)에는 칸마다 **주소**(번지)가 있어요. 강의에서는 RAM 을 크게 두 구역으로 나눠 설명해요.

```
RAM
+---------------------------------------------+
| Heap(힙) 영역   : new 로 만든 객체가 사는 곳  |
|                                             |
|    [100번지] name=손흥민 kor=100 eng=90 ...  |
|        ^                                    |
+--------|------------------------------------+
| Stack(스택) 영역: 보통 변수가 사는 곳          |
|        |                                    |
|    sj [ 100번지 ]   <- 객체의 "주소"를 저장   |
|    b  [ 3 ]         <- int 변수는 값을 바로 저장 |
+---------------------------------------------+
```

- `int b = 3;` 같은 보통 변수는 **스택**에 칸이 생기고, 그 칸에 값 3이 바로 들어가요.
- `new` 로 만든 객체는 **힙**에 자리를 잡아요. 그 자리에는 주소(예: 100번지)가 있어요.
- 이 주소를 변수에 저장해 두면, 그 변수를 통해 객체를 찾아갈 수 있어요.

### 참조 변수

```java
Sungjuk sj = new Sungjuk();
```

- `new Sungjuk()` : 힙에 성적 객체를 만들고, 그 **주소**를 돌려줘요.
- `Sungjuk sj` : 그 주소를 받을 변수 `sj` 를 만들어요.

이렇게 **값 대신 객체의 주소를 저장하는 변수**를 **참조 변수(reference variable)** 라고 해요. 클래스를 "참조 자료형"이라고 부르는 이유가 이거예요. 변수가 객체를 직접 담는 게 아니라 "저기 있어요" 하고 **가리키기(참조하기)** 때문이에요.

비유하면 참조 변수는 **집 주소가 적힌 쪽지**예요. 집(객체)은 힙에 있고, 쪽지(sj)에는 주소만 적혀 있어요. 쪽지를 보고 그 집에 찾아가는 거죠.

주의할 점: 강사가 예로 "100번지"라고 했다고 해서 `sj` 를 `int` 로 선언하면 안 돼요. `sj` 가 가리키는 건 성적 객체니까 **자료형도 반드시 `Sungjuk`** 이어야 해요.

### 그냥 `new Sungjuk();` 만 쓰면?

강의 첫 줄처럼 `new Sungjuk();` 만 쓰면 객체는 만들어지지만 주소를 어디에도 적어 두지 않아서, **만든 객체를 다시 찾아갈 방법이 없어요.** 쪽지 없이 집만 지은 셈이에요. 그래서 실제로는 거의 항상 `클래스명 변수 = new 클래스명();` 형태로 써요.

### 점(.) 연산자로 멤버에 접근하기

```java
sj.name = "손흥민";
sj.kor = 100;
sj.eng = 90;
sj.mat = 80;
sj.calc();
sj.disp();
```

`sj.name` 은 "sj 가 가리키는 객체 **안의** name"이라는 뜻이에요. 점(`.`)을 "~의"로 읽으면 쉬워요. `sj.calc()` 는 "sj 객체**의** calc 메소드를 실행해"예요.

실행 결과

```
손흥민
100
90
80
90
```

평균은 (100 + 90 + 80) / 3 = 270 / 3 = 90 이에요.

순서도 중요해요. `disp()` 를 `calc()` 보다 먼저 부르면 평균이 아직 계산되지 않아서 `0` 이 찍혀요. 값을 안 넣은 `int` 멤버 변수는 자동으로 0 이 들어 있거든요.

## 4. 접근 제어 (Access Modifier)

### 왜 필요할까?

은행 계좌 객체가 있다고 해 봐요. 아무 코드나 `account.balance = 1000000000;` 처럼 잔액을 마음대로 바꿀 수 있으면 큰일이죠. 그래서 "이 멤버는 밖에서 못 건드리게", "이 멤버는 누구나 쓰게" 하고 **문을 잠그거나 열어 두는 장치**가 필요해요. 이게 **접근 제어(access modifier)** 예요. 접근 제한, 접근 수정자라고도 불러요.

접근 제어는 **클래스, 멤버 변수, 멤버 함수, 생성자** 앞에 붙일 수 있어요.

### 네 가지 종류

범위가 좁은 것부터 넓은 것 순서예요. 강의 슬라이드의 동심원 그림처럼 안쪽에서 바깥쪽으로 점점 넓어진다고 생각하면 돼요.

| 접근 제어 | 쓰는 법 | 접근할 수 있는 곳 | 비유 |
|---|---|---|---|
| private | `private` | **같은 클래스 안**에서만 | 내 방 일기장 |
| package | **아무것도 안 씀** | 같은 패키지 안의 클래스 | 우리 집 거실 |
| protected | `protected` | 같은 패키지 + 상속받은 자식 클래스 | 친척까지 들어오는 집 |
| public | `public` | 어디서나 | 동네 공원 |

`protected` 는 상속(15강)을 배워야 의미가 생기니까 지금은 이름만 알아 두면 돼요.

**강의와 다른 점** : 슬라이드에는 두 번째가 "package"라고 적혀 있지만, 자바에 `package` 라는 접근 제어 **키워드는 없어요.** 아무것도 안 쓰는 상태를 보통 "default 접근" 또는 "package-private" 이라고 불러요. 강사도 "생략하면 package 라는 말이 생략된 것이고, 직접 `package` 라고 쓰면 오류난다"고 했는데, 정확히는 "생략된 것"이 아니라 **아무것도 안 쓰는 것 자체가 하나의 접근 수준**이에요. 실제로 `package int kor;` 처럼 쓰면 이런 에러가 나요(javac 21로 확인).

```
error: illegal start of type
```

(맨 위의 `package oop13;` 은 접근 제어가 아니라 "이 파일이 어느 패키지에 있는지" 선언하는 전혀 다른 문장이에요. 아래 7절 참고.)

### 성적 클래스로 확인하기

```java
sj.name = "손흥민";  // name 은 public  -> 가능
sj.kor = 100;        // kor 는 생략(package) -> 같은 패키지라 가능
// sj.aver = 90;     // aver 는 private -> 에러!

sj.calc();           // public  -> 가능
sj.disp();           // 생략(package) -> 가능
// sj.view();        // private -> 에러!
```

주석을 풀고 컴파일하면 javac(21) 가 이렇게 알려 줘요.

```
error: aver has private access in Sungjuk
error: view() has private access in Sungjuk
```

이클립스에서는 빨간 줄과 함께 `The field Sungjuk.aver is not visible` 같은 메시지가 떠요(이클립스 문구는 직접 확인하지 못했어요).

### 같은 클래스 안에서는 접근 제어가 상관없어요

`aver` 는 `private` 인데, `calc()` 안에서는 `aver = ...` 로 아무 문제 없이 써요. private 은 "**클래스 바깥**에서 못 쓰게" 하는 거라, 클래스 자기 자신은 모든 멤버를 자유롭게 써요.

### 그럼 언제 무엇을 붙일까? (실무 약속)

강의에서는 연습하려고 public, 생략, private 을 섞어 썼지만, 실제로 이렇게 **뒤죽박죽 붙이면 안 된다**고 강사가 여러 번 강조해요. 자바 개발자들 사이의 가장 흔한 약속은 이거예요.

- **멤버 변수 -> `private`** (밖에서 값을 마음대로 못 바꾸게 숨겨요. 이걸 **정보 은닉**이라고 해요)
- **멤버 함수 -> `public`** (밖에서는 메소드를 통해서만 객체를 쓰게 해요)

다음 예제의 `School` 클래스가 바로 이 방식이에요. "어느 걸 붙일지 오래 고민하지 말고 이 약속을 따라가라"는 게 강사의 팁이에요.

## 5. private 으로 숨기면 값은 어떻게 넣지?

멤버 변수를 전부 private 으로 막으면 `one.name = "무궁화";` 같은 코드가 에러가 나요. 그럼 값을 어떻게 넣을까요? 방법 중 하나가 바로 **생성자**예요. 객체를 만들 때 값을 넘겨주면, 클래스 **안쪽**에 있는 생성자가 그 값을 private 멤버에 넣어 줘요. (다른 방법인 Setter 함수는 17강에서 배워요.)

## 6. 생성자 함수 (Constructor)

### 생성자란?

**생성자**는 `new` 로 객체가 만들어질 때 **맨 처음 자동으로 한 번 실행되는** 특별한 함수예요. 주로 "객체가 태어나자마자 가져야 할 값(초기값)"을 넣는 데 써요.

비유하면, 붕어빵 틀에서 빵을 찍어낼 때 **"속은 뭘로 넣을까요?"** 하고 주문을 받는 단계예요. 팥을 주문하면 팥붕어빵이, 슈크림을 주문하면 슈크림붕어빵이 처음부터 그 상태로 나오죠.

### 생성자의 규칙

```
접근제어  클래스이름 ( 매개변수 ) {
    처음에 할 일
}
```

1. **이름은 클래스 이름과 똑같아야 해요.** 마음대로 지으면 안 돼요. (`School` 클래스의 생성자는 `School`)
2. **리턴형을 쓰지 않아요.** `void` 도 안 써요. (이 점이 일반 메소드와 가장 크게 다른 점이에요.)
3. 앞에 접근 제어(`public` 등)를 붙일 수 있어요.
4. 매개변수를 다르게 해서 **여러 개** 만들 수 있어요. (11강에서 배운 **오버로드**와 같은 원리예요.)

**참고(강의 밖 내용)** : 강사는 "생성자 함수도 함수이기 때문에 오버로드가 된다"고 설명하는데, 엄밀히 말하면 자바에서 생성자는 **메소드가 아니에요.** 리턴형이 없고, `sj.calc()` 처럼 직접 부를 수도 없고, `new` 할 때만 실행돼요. 다만 "매개변수가 다르면 여러 개 만들 수 있다"는 오버로드 규칙은 메소드와 똑같이 적용되니까, 초보 단계에서는 "특별한 함수" 정도로 이해해도 괜찮아요.

### School 클래스: 생성자 4개

```java
class School {
    private String name;
    private int kor, eng, mat;
    private int aver;

    public School() {}                     // ① 전달값 없음

    public School(String n) {              // ② 문자열 1개
        name = n;
    }

    public School(int k, int e, int m) {   // ③ 정수 3개
        kor = k;
        eng = e;
        mat = m;
    }

    public School(String n, int k, int e, int m) { // ④ 문자열 1개 + 정수 3개
        name = n;
        kor = k;
        eng = e;
        mat = m;
    }

    public void calc() { aver = (kor + eng + mat) / 3; }
    public void disp() { /* name, kor, eng, mat, aver 를 한 줄씩 출력 */ }
}
```

- 멤버 변수는 전부 `private`, 메소드와 생성자는 전부 `public` 이에요. 4절에서 말한 "가장 일반적인 설계 방식"이에요.
- `public School(String n) { name = n; }` : 넘겨받은 문자열 `n` 을 멤버 변수 `name` 에 넣어요. 생성자는 클래스 **안쪽**이라 private 인 `name` 에 접근할 수 있어요.
- 생성자 이름이 네 개 모두 `School` 로 같지만, **매개변수의 개수와 자료형이 달라서** 자바가 서로 다른 생성자로 구별해요.

강사는 클래스 안의 순서를 **멤버 변수 -> 생성자 -> 멤버 함수** 로 쓰는 게 일반적이라고 해요. 순서가 바뀌어도 동작은 같지만, 이렇게 쓰면 읽기 편해요.

### 어떤 생성자가 불릴까?

```java
School one   = new School("무궁화");              // ② 가 불림
School two   = new School(10, 20, 30);            // ③ 이 불림
School three = new School("오필승", 60, 50, 30);  // ④ 가 불림
```

`new School(...)` 의 괄호 안에 넣은 **값의 개수와 자료형**을 보고, 자바가 그에 맞는 생성자를 골라서 실행해요.

- `one` : 문자열 하나 -> ② -> 이름만 들어가고 점수는 0
- `two` : 정수 세 개 -> ③ -> 점수만 들어가고 이름은 비어 있음
- `three` : 문자열 + 정수 세 개 -> ④ -> 전부 들어감

```java
one.calc();   one.disp();
two.calc();   two.disp();
three.calc(); three.disp();
```

- `one` 의 점수는 하나도 안 넣었으니 0, 평균도 0 이에요.
- `two` 의 이름 자리에 **`null`** 이 찍혔어요. `null` 은 "아무것도 가리키지 않는다(비어 있다)"는 뜻의 특별한 값이에요. `"null"` 이라는 글자가 아니에요. 문자열 같은 참조 자료형 멤버에 값을 안 넣으면 자동으로 `null` 이 들어가요.
- `three` 의 평균은 (60 + 50 + 30) / 3 = 140 / 3 = 46.66... 인데, `int` 끼리 나누면 소수점 아래를 **버리기** 때문에 `46` 이 나와요(04강 복습).

### 이클립스로 생성자 자동 만들기

생성자는 워낙 자주 만들어서 이클립스가 대신 써 주는 메뉴가 있어요.

- 메뉴 **Source -> Generate Constructor using Fields...** : 멤버 변수를 골라서 그걸 채우는 생성자를 만들어 줘요.
- 메뉴 **Source -> Generate Constructors from Superclass...** : 강의 [24:46] 에서 강사가 눌러 본 메뉴예요. 전달값 없는 생성자가 만들어져요.

자동으로 만들면 안에 `super();` 와 `// TODO Auto-generated constructor stub` 같은 줄이 같이 생겨요. `super()` 는 18강에서 배우는 내용이고, 강사 말대로 필요 없으면 지워도 돼요.

### 참고(강의 밖 내용): 기본 생성자

강의 첫 예제 `Sungjuk` 에는 생성자를 하나도 안 썼는데도 `new Sungjuk()` 이 잘 됐죠? **생성자를 하나도 안 쓰면 자바가 아무 일도 안 하는 `Sungjuk() {}` 를 몰래 만들어 주기** 때문이에요. 이걸 **기본 생성자**라고 해요.

그런데 생성자를 **하나라도 직접 쓰면** 자바는 더 이상 기본 생성자를 만들어 주지 않아요. 그래서 `School(String n)` 만 만들고 `public School() {}` 를 빼 버리면 `new School()` 이 에러가 나요. 강의 `School` 에 빈 생성자 ①을 일부러 넣어 둔 이유가 여기 있어요. (`code/DefaultConstructor.java` 에서 확인할 수 있어요.)

## 7. package 와 import (짧게)

강의 중간에 파일 맨 위의 두 문장도 설명해요.

```java
package oop13;       // 이 클래스가 저장된 위치(폴더). 파일에 한 번만 써요
import java.util.*;  // 다른 패키지의 클래스를 가져다 쓰겠다는 선언. 여러 번 써도 돼요
```

- **package** : 클래스를 담는 폴더 같은 거예요. 패키지 안에 또 패키지를 넣을 수 있고, 구분은 점(`.`)으로 해요. 한 `.java` 파일에 한 번만 써요.
- **import** : 다른 패키지에 있는 클래스를 쓰려면 "그 클래스가 어디 있는지" 알려 줘야 해요. `java.util.*` 의 `*` 는 "java 패키지 안의 util 패키지 안에 있는 **모든 클래스**"라는 뜻이에요. 우리가 만든 패키지(`oop12.*` 등)도 import 할 수 있어요.

이 노트의 `code/` 예제는 터미널에서 바로 실행하기 쉽게 `package` 선언 없이 만들었어요. 그래도 같은 폴더의 클래스끼리는 같은 패키지(이름 없는 패키지)로 취급돼서, "생략(package)" 접근 멤버를 서로 쓸 수 있어요.

## 8. 정리

- 클래스 = 설계도, 객체 = 설계도로 찍어낸 실물. 클래스는 내가 만드는 **참조 자료형**이에요.
- 클래스 = 멤버 변수(필드, 속성) + 멤버 함수(메소드, 기능) + 생성자.
- `new 클래스명()` 은 힙에 객체를 만들고 주소를 돌려줘요. 그 주소를 담는 변수가 **참조 변수**예요.
- 점(`.`) 연산자로 "그 객체의 ~"에 접근해요.
- 접근 제어 범위: private < (생략) < protected < public. 같은 클래스 안에서는 상관없어요.
- 보통 멤버 변수는 private, 메소드와 생성자는 public 으로 설계해요.
- 생성자는 클래스 이름과 같고 리턴형이 없으며, `new` 할 때 처음 실행돼요. 매개변수를 다르게 해서 여러 개 만들 수 있어요(오버로드).

| `error: incompatible types: Sungjuk cannot be converted to int` | 객체 주소를 `int` 변수에 담으려 했어요 (`int sj = new Sungjuk();`) | 참조 변수의 자료형은 클래스 이름으로: `Sungjuk sj = new Sungjuk();` |

| 출력에 `null` 이 찍혀요 (에러는 아님) | 문자열 같은 참조형 멤버에 값을 넣지 않았어요 | 생성자나 대입으로 값을 넣어요 |

| `The public type ... must be defined in its own file` (이클립스) | 한 파일에 `public class` 를 두 개 썼어요 | public 클래스는 파일당 하나. 나머지는 `public` 을 빼거나 파일을 나눠요 (이 문구는 직접 확인 못 했어요) |

## 용어 정리

| 용어 | 쉬운 뜻 |
|---|---|
| 클래스 (class) | 객체를 만들기 위한 설계도. 내가 만드는 자료형 |
| 객체 (object) / 인스턴스 | 클래스로 실제로 만들어 낸 것. 힙 메모리에 생겨요 |
| 멤버 변수 (필드, field) | 클래스 안에 선언한 변수. 객체가 가진 값(속성) |
| 멤버 함수 (메소드, method) | 클래스 안에 만든 메소드. 객체가 할 수 있는 일(기능) |
| 생성자 (constructor) | 객체가 만들어질 때 맨 처음 실행되는 특별한 함수. 이름 = 클래스 이름, 리턴형 없음 |
| 기본 생성자 | 생성자를 하나도 안 쓰면 자바가 자동으로 넣어 주는 빈 생성자 |
| new | 클래스로 객체를 만드는(메모리를 확보하는) 연산자 |
| 힙 (heap) | new 로 만든 객체가 저장되는 메모리 구역 |
| 스택 (stack) | 보통 변수(지역 변수)가 저장되는 메모리 구역 |
| 참조 변수 (reference) | 객체의 주소를 저장해서 객체를 가리키는 변수 |
| 참조 자료형 | 값이 아니라 주소를 다루는 자료형. 클래스, 배열, String 등 |
| 점(.) 연산자 | "그 객체의 ~". 참조 변수로 멤버에 접근할 때 써요 |
| 접근 제어 (access modifier) | 멤버를 어디서 쓸 수 있는지 정하는 키워드 |
| private | 같은 클래스 안에서만 쓸 수 있음 |
| (생략) / package-private | 같은 패키지 안에서만 쓸 수 있음. 키워드를 안 써요 |
| protected | 같은 패키지 + 상속받은 클래스에서 쓸 수 있음 |
| public | 어디서나 쓸 수 있음 |
| 정보 은닉 | 멤버 변수를 private 으로 숨겨 밖에서 함부로 못 바꾸게 하는 것 |
| 오버로드 (overload) | 이름은 같고 매개변수가 다른 메소드·생성자를 여러 개 만드는 것 |
| null | "아무 객체도 가리키지 않음"을 뜻하는 특별한 값 |
| package | 클래스를 묶어 두는 폴더 같은 단위. 파일 맨 위에 한 번 선언 |
| import | 다른 패키지의 클래스를 쓰겠다고 알리는 선언 |
