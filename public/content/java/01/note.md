# 01강. 자바 개념 및 교육 소개

## 이 강의에서 배우는 것

- 프로그램과 프로그래밍(코딩)이 무엇인지, 왜 "프로그래밍 언어"라는 중간 다리가 필요한지 알아봐요.
- 저급 언어와 고급 언어의 차이, 그리고 번역기인 컴파일러와 인터프리터의 차이를 배워요.
- 자바 소스 파일(`.java`)이 번역되어 `.class` 파일이 되는 흐름을 이해해요.
- 자바의 대표 특징(플랫폼 독립성, 자동 메모리 관리, 객체지향)과 자바로 만들 수 있는 것들을 살펴봐요.
- 앞으로 이 강좌가 어떤 순서(기본 문법 -> 객체지향 -> 활용)로 진행되는지 알아봐요.

---

## 1. 프로그램과 프로그래밍

### 프로그램
**프로그램**은 컴퓨터가 어떤 문제를 해결하도록 "무엇을, 어떤 순서로 할지"를 적어 놓은 **명령문들의 모음**이에요. 완성된 결과물이라고 생각하면 돼요. 컴퓨터는 생각을 하지 않고, 프로그램에 적힌 명령을 적힌 순서대로 그대로 실행할 뿐이에요. 그래서 프로그램을 "잘" 만들어 두는 게 중요해요.

> 비유: 프로그램은 **요리 레시피**예요. "물 500ml를 끓인다 -> 면을 넣는다 -> 4분 기다린다"처럼 순서가 적혀 있고, 요리사(컴퓨터)는 레시피에 적힌 대로만 움직여요. 레시피에 소금을 빼먹으면 요리사도 소금을 안 넣어요.

### 프로그래밍 (= 코딩)
그 레시피를 **쓰는 기술**이 **프로그래밍**이에요. 머릿속의 해결 방법(이걸 **알고리즘**이라고 해요)을 특정 프로그래밍 언어로 구체적으로 옮겨 적는 일이죠. 같은 말로 **코딩**이라고도 해요.

| 구분 | 뜻 |
|---|---|
| 프로그램 | 결과물 (명령문 모음, 레시피 자체) |
| 프로그래밍 / 코딩 | 결과물을 만드는 기술/행위 (레시피를 쓰는 일) |

---

## 2. 왜 프로그래밍 언어가 필요할까?

- 사람은 **자연어**(한국어, 영어처럼 일상에서 쓰는 말과 글)로 대화해요.
- 컴퓨터는 기계라서 **0과 1**(전기 신호가 꺼짐/켜짐)만 알아들어요. 이것을 **기계어**라고 해요.

일을 시키는 쪽(사람)과 일을 하는 쪽(컴퓨터)이 쓰는 언어가 완전히 달라서 그대로는 대화가 안 돼요. 그래서 둘 사이에서 **통역사 역할**을 하는 언어가 필요한데, 그게 바로 **프로그래밍 언어**예요.

```
사람(자연어)  --->  프로그래밍 언어로 명령 작성  --->  번역  --->  컴퓨터(0과 1)
```

> 비유: 한국어만 하는 사장님이 영어만 하는 직원에게 일을 시키려면 통역사가 필요하죠. 프로그래밍 언어가 그 통역사 자리에 서는 셈이에요.

---

## 3. 저급 언어와 고급 언어

프로그래밍 언어는 종류가 아주 많은데, 크게 두 부류로 나눌 수 있어요. ("저급/고급"은 좋고 나쁨이 아니라 **기계에 가까운지, 사람에 가까운지**를 말해요.)

| 구분 | 특징 | 예 |
|---|---|---|
| **저급 언어** | 기계어(0과 1)에 가까움. 컴퓨터는 바로 이해하지만 사람이 읽기 매우 어려움 | 기계어, 어셈블리어 |
| **고급 언어** | 사람이 읽기 쉬운 단어와 기호로 작성. 컴퓨터가 실행하려면 번역이 필요 | 자바, 파이썬, C++ 등 |

요즘 일상적으로 쓰는 언어는 거의 다 고급 언어예요. 자바도 고급 언어고요.

---

## 4. 컴파일러와 인터프리터 (번역기 두 가지)

고급 언어로 쓴 코드를 **소스 코드(원시 코드)**라고 해요. 컴퓨터는 소스 코드를 그대로 이해하지 못하니까 기계가 알아듣는 코드로 **번역**해야 해요. 번역 방식은 두 가지예요.

| | 인터프리터 (Interpreter) | 컴파일러 (Compiler) |
|---|---|---|
| 번역 방식 | **한 문장씩** 읽고 바로 해석해서 실행 | 소스 코드 **전체를 한꺼번에** 읽어서 번역 |
| 결과 | 따로 번역 파일을 남기지 않음 | **목적 코드**(번역된 파일)를 만들고, 필요할 때 실행 |
| 대표 언어 | 파이썬, 자바스크립트, 루비 | 자바, C, C++ |

> 비유: 인터프리터는 **동시통역사**(한 문장 들을 때마다 바로 통역), 컴파일러는 **번역가**(책 한 권을 통째로 번역해서 번역본을 만들어 둠)예요.

"번역기는 어디서 구하나요?" 하고 궁금할 수 있는데, 자바 개발 도구(JDK)를 설치하면 그 안에 컴파일러가 들어 있어요. 따로 구할 필요 없어요. (설치는 02강에서 해요.)

### 자바 파일의 흐름: `.java` -> `.class`

```
HelloWorld.java   --(컴파일러 javac가 번역)-->   HelloWorld.class   --(JVM이 실행)-->   화면 출력
 (소스 코드)                                       (목적 코드)
```

- 사람이 작성하는 자바 소스 파일의 확장자는 **`.java`** 예요.
- 컴파일러가 번역한 결과 파일의 확장자는 **`.class`** 예요. 완성된 자바 프로그램을 다른 사람에게 나눠줄(배포할) 때는 이 `.class` 쪽을 줘요.
- 어디서든 `.java`나 `.class` 파일을 보면 "아, 자바 관련 파일이구나" 하고 알아보면 돼요.

> 조금 더 정확히: 자바의 `.class` 파일 안에 든 것은 CPU가 바로 실행하는 기계어가 아니라 **바이트코드**라는 중간 코드예요. 이것을 아래에서 설명할 **JVM**이 받아서 실제 컴퓨터에 맞게 실행해 줘요. 지금은 "자바는 컴파일해서 .class를 만든다" 정도만 기억하면 충분해요.

### 직접 해보기 (맛보기)
`code/HelloWorld.java` 파일로 흐름을 체험할 수 있어요. 아직 설치가 안 됐다면 02강을 먼저 보고 와도 돼요.

```java
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, Java!");
        System.out.println("나의 첫 자바 프로그램");
    }
}
```

- `public class HelloWorld` : HelloWorld라는 이름의 클래스(자바 프로그램의 기본 단위 상자)를 만들어요. 파일 이름도 `HelloWorld.java`여야 해요.
- `public static void main(String[] args)` : 프로그램이 시작되는 입구예요. 자바는 항상 여기서부터 실행해요.
- `System.out.println("...")` : 따옴표 안의 글자를 화면에 출력하고 줄을 바꿔요.

터미널에서:
```
javac -encoding UTF-8 HelloWorld.java
java HelloWorld
```
실행 결과:
```
Hello, Java!
나의 첫 자바 프로그램
```
`javac` 명령 뒤에 폴더를 보면 `HelloWorld.class`가 새로 생겨 있어요. 이게 바로 번역된 목적 코드예요.

## 5. 자바는 얼마나 쓰일까?

자바는 아주 오랫동안 개발자들에게 사랑받아 온 언어예요. 언어 인기 순위에서 오랫동안 최상위권을 지켜 왔고, 최근 파이썬이 앞서는 경우도 있지만 여전히 가장 큰 시장 중 하나를 가지고 있어요. 다만 **순위가 언어의 좋고 나쁨을 정하는 건 아니에요.** 만들고 싶은 것에 맞는 언어를 고르면 돼요.

---

## 6. 절차지향 언어와 객체지향 언어

| | 절차지향 (절차형) | 객체지향 |
|---|---|---|
| 핵심 | **순서**가 가장 중요. 위에서 아래로 적힌 순서대로 실행 | 기능과 데이터를 **객체**라는 덩어리로 묶어 두고 필요할 때 불러 씀 |
| 구성 단위 | 함수 | 객체(클래스) |
| 예 | C | 자바, C++, 파이썬 |

> 비유: 절차지향은 **조립 설명서**(1번 -> 2번 -> 3번 순서대로), 객체지향은 **레고 부품 상자**(바퀴 부품, 창문 부품을 미리 만들어 두고 필요할 때 꺼내 조립)예요.

요즘 나오는 언어는 대부분 객체지향 언어예요. (참고: 강의 중 "C"도 객체지향 예로 언급되는데, 일반적으로 C는 절차지향 언어이고 C++가 객체지향 언어예요.)

## 7. 자바의 특징

강사님 말처럼 아래 특징들은 예전엔 자바만의 자랑이었지만, 지금은 많은 고급 언어가 비슷하게 가지고 있어요. 그래도 자바를 이해하는 핵심이니 알아 두세요.

### (1) 플랫폼 독립성 - JVM 덕분
- **플랫폼**(운영체제, OS) : 윈도우, 맥OS, 리눅스, 안드로이드처럼 컴퓨터를 움직이는 기본 프로그램이에요.
- 예전에는 "윈도우용으로 만들지, 리눅스용으로 만들지"를 정하고 그에 맞춰 프로그램을 따로 짰어요.
- 자바 프로그램은 **JVM(Java Virtual Machine, 자바 가상 머신)** 위에서 돌아가요. JVM이 각 OS에 맞게 설치되어 있으면, 같은 `.class` 파일이 어느 OS에서든 실행돼요. 이것을 **플랫폼 독립성**이라고 해요.

```
     내 자바 프로그램 (.class)
              |
     자바 가상 머신 (JVM)   <- OS마다 맞는 JVM이 깔려 있음
              |
  Windows / macOS / Linux / Android ...
```

> 비유: JVM은 **만능 어댑터**예요. 나라마다 콘센트 모양이 달라도 어댑터만 끼우면 같은 충전기를 쓸 수 있듯이, OS가 달라도 JVM만 있으면 같은 자바 프로그램이 돌아가요.

### (2) 자동 메모리 관리
프로그램은 실행 중에 메모리(작업 공간)를 빌려 쓰고, 다 쓰면 돌려줘야 해요. 어떤 언어는 이걸 개발자가 직접 해야 하는데, 자바는 JVM이 **안 쓰는 메모리를 알아서 찾아 정리**해 줘요. (이 청소부 기능을 "가비지 컬렉션"이라고 부르는데, 나중에 배워요.)

### (3) 객체지향 언어
자바는 대표적인 객체지향 언어라서 객체지향의 특징을 모두 가지고 있어요. 지금은 이름만 들어 두면 되고, 2단계에서 하나씩 실습해요.
- **캡슐화** : 관련된 데이터와 기능을 하나로 묶기
- **정보 은닉** : 바깥에서 함부로 못 건드리게 숨기기
- **추상화** : 꼭 필요한 핵심만 뽑아내기
- **상속** : 이미 만든 것을 물려받아 재사용하기
- **다형성** : 같은 명령이 상황에 따라 다르게 동작하기

이런 특징 덕분에 코드를 **재사용**하기 쉽고, 프로그램을 빨리 만들 수 있어요(생산성 향상).

## 8. 자바로 무엇을 만들 수 있을까? (응용 분야)

| 분야 | 설명 |
|---|---|
| 웹 프로그래밍 | 자바 기반의 웹 기술(JSP, 스프링 프레임워크)로 홈페이지의 뒤쪽 동작(백엔드)을 만들어요. 화면(프론트엔드)에는 HTML, CSS, 자바스크립트도 함께 필요해요. |
| 안드로이드 앱 | 안드로이드 폰에서 돌아가는 앱과 게임을 만들 수 있어요. |
| 윈도우(데스크톱) 프로그램 | 메모장, 그림판 같은 PC 프로그램도 만들 수 있어요. |
| 게임 프로그래밍 | 다양한 게임 개발에도 쓰여요. |
| 빅데이터 | 인터넷의 정보를 모으는 **크롤링**, 그래프로 보여주는 **시각화**, 글에서 의미를 뽑는 **텍스트 마이닝**용 라이브러리가 자바에도 많아요. |

## 9. 교육 소개 - 이 강좌의 3단계

1. **1단계: 프로그래밍 언어 기본 문법** - 변수, 자료형, 출력, 조건문, 반복문, 배열 등. 자바뿐 아니라 파이썬, C 등 어떤 언어를 배우든 꼭 거치는 공통 기초예요.
2. **2단계: 객체지향 프로그래밍** - 클래스, 상속, 다형성, 예외 처리 등. 요즘 언어 대부분이 객체지향이라 다른 언어를 배울 때도 도움이 돼요.
3. **3단계: 자바 활용** - 1, 2단계에서 배운 것으로 간단한 활용 실습을 해요.

### 공부 팁 (강사 추천)
- 강의 전에 그 강의의 목표를 꼭 확인하기
- 실습은 **영상을 멈추고 직접 타이핑**해 보기 (눈으로만 보면 안 남아요)
- 수업에 나온 핵심 키워드를 인터넷에 직접 검색해 보기
- 배운 내용을 블로그 같은 곳에 요약 정리하기
- 준비물: 인터넷이 되는 컴퓨터나 노트북

## 자주 하는 실수 (개념 편)

01강은 코드를 거의 안 쓰지만, 개념을 헷갈리면 다음 강의에서 막혀요.

| 헷갈리는 점 | 바로잡기 |
|---|---|
| "`.class` 파일을 열어서 고치면 되겠지?" | `.class`는 번역된 결과물이라 사람이 읽고 고치는 파일이 아니에요. 항상 `.java`를 고친 다음 **다시 컴파일**해야 바뀐 내용이 반영돼요. |
| `.java` 파일을 고쳤는데 결과가 그대로예요 | 고친 뒤 `javac`로 다시 컴파일하지 않았을 가능성이 커요. (Eclipse 같은 도구는 저장하면 자동으로 컴파일해 줘요.) |
| 파일 이름과 클래스 이름이 달라요 | `public class HelloWorld`라면 파일 이름도 정확히 `HelloWorld.java`여야 해요. 다르면 `class HelloWorld is public, should be declared in a file named HelloWorld.java` 에러가 나요. 대소문자도 구분해요. |
| `java HelloWorld.class`라고 실행했어요 | 실행할 때는 확장자 없이 `java HelloWorld`예요. (`.class`를 붙이면 `Could not find or load main class` 에러가 나요.) |
| "저급 언어 = 나쁜 언어" | 저급/고급은 품질이 아니라 **기계와 얼마나 가까운가**를 말해요. |

## 용어 정리

| 용어 | 쉬운 뜻 |
|---|---|
| 프로그램 | 컴퓨터에게 할 일을 순서대로 적어 둔 명령문 모음 (레시피) |
| 프로그래밍 / 코딩 | 프로그램을 작성하는 기술, 행위 |
| 알고리즘 | 문제를 푸는 방법과 순서 |
| 자연어 | 사람이 일상에서 쓰는 말과 글 |
| 기계어 | 컴퓨터가 직접 이해하는 0과 1로 된 언어 |
| 저급 언어 | 기계어에 가까운 언어 (기계어, 어셈블리어) |
| 고급 언어 | 사람이 읽기 쉬운 언어 (자바, 파이썬 등) |
| 소스 코드 (원시 코드) | 사람이 고급 언어로 작성한 코드. 자바에서는 `.java` 파일 |
| 번역 | 소스 코드를 컴퓨터가 실행할 수 있는 형태로 바꾸는 과정 |
| 컴파일러 | 소스 코드 전체를 한꺼번에 번역해 결과 파일을 만드는 번역기 (자바는 `javac`) |
| 인터프리터 | 소스 코드를 한 문장씩 읽으며 바로 실행하는 번역기 |
| 목적 코드 | 번역된 결과 코드. 자바에서는 `.class` 파일 |
| 바이트코드 | 자바 `.class` 안에 들어 있는 중간 코드. JVM이 실행함 |
| JVM (자바 가상 머신) | 자바 프로그램을 실행해 주는 프로그램. OS마다 맞는 버전이 있음 |
| 플랫폼 (OS, 운영체제) | 윈도우, 맥OS, 리눅스, 안드로이드처럼 컴퓨터의 기본 바탕 프로그램 |
| 플랫폼 독립성 | OS가 달라도 같은 프로그램이 실행되는 성질 |
| 자동 메모리 관리 | 안 쓰는 메모리를 JVM이 알아서 정리해 주는 기능 |
| 절차지향 | 순서대로 실행하는 것을 중심으로 짜는 방식 |
| 객체지향 | 데이터와 기능을 객체로 묶어 조립하듯 짜는 방식 |
| 배포 | 만든 프로그램을 다른 사람이 쓸 수 있게 나눠 주는 것 |
| 라이브러리 | 남이 미리 만들어 둔, 가져다 쓸 수 있는 코드 묶음 |
| 크롤링 | 인터넷의 정보를 자동으로 모으는 작업 |
